# 可视化插件与运行数据标准（入门版）

> 正式规范（字段表、版本规则）见 [run-data-format.md](run-data-format.md)。这篇用大白话讲清楚"为什么这样设计"和"插件怎么写"。

## 一句话

**browser-recipewright 本身不带可视化界面。** 每次运行，它都会在本地写下一套固定格式的记录文件；
可视化界面是单独下载的"插件"，只负责**读**这些文件，再把它们变成好看的画面。

```
  执行器（run / batch / demo）               可视化插件（单独下载，可以有很多个）
  ┌──────────────────────┐   只追加写入    ┌──────────────────────────────┐
  │ 打开网页、点击、滚动、 │ ─────────────▶ │ ~/.browser-recipewright/runs/ │ ◀── 只读
  │ 提取数据……           │                │   run.json  events.jsonl …    │
  └──────────────────────┘                └──────────────────────────────┘
```

## 为什么不把界面打包进来

- **执行器保持小而稳。** 浏览器自动化的核心不受界面代码影响；界面出 bug，不会让一次采集失败。
- **界面想怎么做都行。** 白色简洁风、炫酷 3D、终端文字、网页报表……只要读同一份数据，风格完全不受限制。
- **任何语言都能写插件。** 数据就是普通的 JSON 文件，Python、网页、Swift 都能读，不需要引入本项目的代码。
- **随时回放。** 每次运行都会写记录（不需要开关），插件可以实时看正在跑的任务，也能回放昨天的任务。

## 数据长什么样

每次运行一个文件夹，例如 `~/.browser-recipewright/runs/2026-11-24T12-13-47_demo-local-feed_sbxe/`：

| 文件 | 作用 | 打个比方 |
| --- | --- | --- |
| `run.json` | 这次运行的概况：哪个配方、什么时候开始、结果是成功还是失败 | 封面 |
| `events.jsonl` | **事件流**：一行一件事，按发生顺序追加 | 逐帧的"录像带" |
| `steps.jsonl` | 每个步骤结束后的详细记录（试了哪些定位方式、耗时等） | 详细笔记 |
| `output.json` | 最终采集到的数据 | 成品 |
| `artifacts/`、`failure/` | 截图、下载的文件、失败时给 AI 看的诊断包 | 附件 |

另外 `runs/_latest.json` 永远指向**最新的一次运行**，插件盯住它，就能知道"有新任务开始了"。

`events.jsonl` 里的一行长这样：

```json
{"v":1,"seq":9,"t":"2026-11-24T12:13:11.685Z","ms":1177,"type":"pointer.move","x":727,"y":674,"fromX":519,"fromY":427,"durationMs":412}
```

意思是：第 9 件事，运行开始后 1.177 秒，鼠标用 0.412 秒从 (519, 427) 弧线移动到了 (727, 674)。
每一行都有 `v`（版本）、`seq`（序号）、`t`（时间）、`ms`（距离开始的毫秒数）、`type`（事件类型）这五个字段。

## 能做出哪些效果（对应哪些事件）

| 想做的效果 | 读哪些事件 |
| --- | --- |
| 开始前就画出整张"配方流程图" | `run.start` 里的 `steps`（配方大纲） |
| 当前执行到哪一步、每步成功/失败/重试 | `step.start`、`step.end`、`step.retry` |
| 循环的第几条（例如"第 3/30 个岗位"） | `loop.iteration` |
| 采集到的数据一条条流进"数据栏" | `data`（带前 3 条预览） |
| 鼠标轨迹、点击波纹、滚动动画 | `pointer.move`、`pointer.click`、`pointer.wheel`、`page.viewport` |
| 正在打字（只给字数，不记录内容，保护隐私） | `key.type` |
| 网页地址变化、镜像网页 | `page.navigated`，截图见 `artifact` |
| "需要人工处理"提示（登录、验证码） | `handoff.start`、`handoff.end` |
| 结束画面、成功率统计 | `run.end` |

## 写一个插件只需要四步

1. 找到要看的运行：用户给的文件夹，或者读 `runs/_latest.json`。
2. 读 `run.json`，确认 `format` 是 `{"name": "recipewright.run", "version": 1}`。
3. 从头一行行读 `events.jsonl`；要看"直播"，就记住读到的位置，文件变长了再接着读。
   **最后一行如果还没有换行符，说明还没写完，等一下再读。**
4. 读到 `run.end` 就结束。

不想写读文件的代码？直接用命令行把事件"喂"给你的插件：

```bash
browser-recipewright events -f | 你的插件      # 跟随最新一次运行，一行一个事件
browser-recipewright check-run                # 检查一次运行的数据是否符合标准
```

完整示例（约 90 行，零依赖，终端里显示时间线）：[examples/viewer-plugin-minimal](../examples/viewer-plugin-minimal)。

## 插件要遵守的三条规矩

1. **只读。** 不往数据文件夹里写任何东西，也不去控制浏览器。
2. **不认识的就跳过。** 以后版本可能会新增事件类型或字段，插件遇到不认识的直接忽略，不要报错。
3. **看版本号。** `v` 不是 1 的数据，说明标准有了不兼容的升级，提示用户更新插件，不要硬猜。
